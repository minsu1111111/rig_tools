# rig_tools — 카메라 시점 고정

카메라를 매번 분해·재장착해야 하는 리그에서, **같은 시점을 재현**하고 틀어지면 수집을 막는 도구.

로봇 데이터셋에서 카메라가 조용히 움직이면 정책은 픽셀→행동 매핑을 두 벌 학습하게 되고,
그건 보통 **학습이 실패한 뒤에야** 발견된다. 수집 전에 30초 확인하면 그 자리에서 막을 수 있다.

| 파일 | 역할 |
|---|---|
| `rig_check.py` | 저장한 기준 화면과 현재 화면 비교. **메인 도구** |
| `rig_focus.py` | 렌즈 초점 맞출 때 선명도 실시간 표시 |
| `rig_common.py` | 공용 모듈 (직접 실행 안 함) |
| `cam_setup.sh` | 노출·화이트밸런스 수동 고정 (V4L2) |

마커가 필요 없다. **화면에 찍힌 정지 구조물 자체를 기준으로** 삼기 때문이다.

요구사항: Python 3, OpenCV(`opencv-python`), 리눅스면 `v4l-utils`(cam_setup.sh용).

---

## 최초 1회 셋업

카메라를 원하는 위치에 두고 기준 화면과 임계값을 저장한다.

```bash
python rig_tools/rig_check.py --camera /dev/video0 --profile mycam \
  --width 640 --height 480 --roi 0,0,1.0,0.4 \
  --update --max-shift 3 --min-correlation 0.85
```

출력에 이 두 줄이 나와야 저장된 것:
```
windows   : [[0, 0, 640, 192]]
limits    : shift <= 3.0, corr >= 0.85
```

임계값을 안 주면 기본값(20px / 0.80)으로 도는데 **너무 느슨해서 카메라를 밀어도 통과한다.**
자기 리그에 맞는 값은 `--suggest`로 잰다(아래).

> `--update`는 기준 화면도 지금 화면으로 새로 저장한다. 카메라가 원하는 위치에 있을 때만 실행할 것.

프로파일은 `rig_tools/profiles/<이름>/`에 `profile.json` + `reference.png`로 저장되고,
이후엔 `--profile <이름>`만 쓰면 영역·임계값이 자동 적용된다.

## 매 세션 사용법

```bash
python rig_tools/rig_check.py --camera /dev/video0 --profile mycam
```

`레퍼런스 | 현재 | 오버레이` 3분할 창이 뜬다. 오버레이는 기준=초록, 현재=마젠타, **맞으면 회색**.
상단 배너가 **초록(OK)** 이 될 때까지 마운트를 조정하고 `q`로 종료.

키: `q`/`ESC` 종료, `SPACE` 현재 화면으로 기준 재저장(구도를 바꿨을 때만)

### 수집 게이트

종료코드가 0(통과)/1(드리프트)이라 스크립트로 막을 수 있다.

```bash
#!/usr/bin/env bash
set -e
python rig_tools/rig_check.py --camera /dev/video0 --profile mycam --quiet \
  || { echo "시점이 틀어졌습니다. 창 모드로 맞추고 다시 실행하세요."; exit 1; }
lerobot-record ...
```

## 명령어 정리

```bash
# 창 없이 판정만
python rig_tools/rig_check.py --camera /dev/video0 --profile mycam --no-display

# 종료코드만 (스크립트용)
python rig_tools/rig_check.py --camera /dev/video0 --profile mycam --quiet

# JSON 출력
python rig_tools/rig_check.py --camera /dev/video0 --profile mycam --json

# 기준 재저장
python rig_tools/rig_check.py --camera /dev/video0 --profile mycam --update
```

`--camera`는 `/dev/video0`, 인덱스(`0`), **또는 이미지 파일**을 받는다.
이미지 파일이면 창 없이 동작하므로 **이미 찍은 데이터셋 프레임도 검사할 수 있다.**

```bash
ffmpeg -ss 0.05 -i episode.mp4 -frames:v 1 f.png
python rig_tools/rig_check.py --camera f.png --profile mycam --json
```

## 비교 영역 고르기 — 여기가 핵심이다

비교할 영역을 `x,y,w,h`로 지정한다 (1 이하 값은 비율, 초과는 픽셀).

**움직이지 않는 것만 넣고, 움직이는 것은 전부 빼라.** 로봇 팔, 조작 대상, 사람이 드나드는 구역은 빼야 한다.
남길 것은 고정된 지그·용기·테이블 모서리·벽에 붙은 무늬처럼 **세션 내내 제자리인 구조물**이다.

이게 성능을 좌우한다. 한 리그에서 측정한 값:

| 영역 | 시점이 같은데 FAIL(오탐) |
|---|---|
| 전체 화면 | 14개 중 **10개** |
| 정지 구조물만 | **0개** |

영역이 팔을 물면 팔이 움직일 때마다 오탐이 나고, 반대로 너무 좁으면 상관을 잡을 구조가 부족해진다.
창에 영역이 노란 사각형으로 그려지니 보면서 맞추면 된다.

### 영역을 자동으로 찾기

어디가 고정인지 판단이 어려우면 도구가 찾아준다.

```bash
python rig_tools/rig_check.py --camera /dev/video0 --profile mycam --suggest-roi 20
```

프레임을 모으면서 **시간에 따라 안 변하면서 질감이 있는** 영역을 골라 `--roi` 플래그로 출력한다.
돌아가는 동안 **로봇과 대상물을 계속 움직여야 한다** — 그 움직임이 "여기는 피하라"는 신호다.

제안값은 출발점이다. 창에 띄워서 팔이나 대상물을 물고 있지 않은지 눈으로 확인하고 쓸 것.

### 여러 영역 지정

플래그를 반복하거나 `;`로 나눈다. 가운데(팔이 지나가는 곳)를 건너뛰고 좌·우만 보는 식이다.

```bash
--roi 0,0,0.3,0.65 --roi 0.7,0,0.3,0.65
--roi "0,0,0.3,0.65; 0.7,0,0.3,0.65"      # 한 줄로도 가능
```

판정은 **보수적으로** 합친다 — shift는 영역 중 최댓값, correlation은 최솟값. 한 영역만 틀어져도 FAIL이다.

영역별 내역이 따로 나오는데, 이게 **원인 구분**에 쓰인다:

```
windows     : 2  (worst values shown above)
  [0] [0, 0, 96, 156]     dx  +0.75 dy -52.01  shift 52.01  corr 0.175
  [1] [224, 0, 96, 156]   dx  -0.61 dy -42.59  shift 42.59  corr 0.697
```

- **모든 영역이 같이 움직임** → 카메라가 이동한 것
- **한 영역만 움직임** → 그 영역의 물건이 밀린 것

많이 틀어진 영역은 창에서 주황색으로 바뀐다.
구도를 바꾸면 영역도 다시 잡아야 한다. 옛 프로파일의 단일 `[x,y,w,h]` 형식도 그대로 읽힌다.

## 임계값 재측정

```bash
python rig_tools/rig_check.py --camera /dev/video0 --profile mycam --suggest 15
```

30초 동안 15장을 샘플링해서 관측된 변동폭에 여유를 준 값을 제안하고, 저장 명령까지 출력한다.

**그동안 로봇과 대상물을 실제로 움직여야 한다.** 정지 상태로 재면 지나치게 빡빡한 값이 나와서
수집 중에 계속 막힌다(샘플이 전부 같으면 경고가 뜬다).

## 노출·화이트밸런스 고정

```bash
./rig_tools/cam_setup.sh /dev/video0 3000 4600     # 장치, 노출, WB 색온도
```

자동 노출은 화면에서 제일 밝은 곳에 물려서 **밝은 물체를 흰색으로 날려버린다.** 색으로 구분해야 하는
태스크라면 그것만으로 학습이 불가능해진다. 자동 화이트밸런스는 세션마다 색을 바꿔서 같은 문제를 만든다.

**V4L2 설정은 재부팅·USB 재연결 시 초기화되므로 매 세션 수집 직전에 실행할 것.**

적정값은 리그마다 다르니 노출을 훑어보면서 정한다 — 대상 색이 살아 있으면서 배경이 뭉개지지 않는 지점.

## 렌즈 초점

```bash
python rig_tools/rig_focus.py --camera /dev/video1 --target 40
```

`현재 영상 | 에지 영상` 창에 선명도와 peak가 뜬다. 렌즈를 돌려 peak가 더 안 오르는 지점을 찾는다.

측정 시 주의:
- **질감 있는 대상**을 봐야 한다. 무늬 없는 면을 보면 초점과 무관하게 숫자가 낮다
- **실제 작업 거리**에서 재야 한다
- 절대 숫자보다 **peak 위치**가 중요하다

키: `r` peak 리셋, `s` 스냅샷, `q` 종료

## 트러블슈팅

**`error: cannot open camera`**
다른 프로세스가 잡고 있다. 카메라는 한 번에 한 프로세스만 연다.

```bash
fuser -v /dev/video0
```

LeRobot이라면 보통 `lerobot-teleoperate`가 범인이다. 카메라 없이 텔레오퍼레이션하려면
`--robot.cameras` 인자를 빼면 된다(기본값이 빈 dict).
수집 시엔 `rig_check`(종료) → `lerobot-record`(카메라 인계) 순서라 겹치지 않는다.

**`ioctl(VIDIOC_QBUF): Bad file descriptor`**
OpenCV가 카메라를 닫을 때 내는 경고. 무시해도 된다.

**항상 OK만 뜬다**
임계값이 저장 안 됐을 수 있다. `profile.json`에 `max_shift`가 있는지 확인.
없으면 기본값 20px이라 웬만해선 안 걸린다.

**OK가 뜬다고 구도가 좋다는 뜻은 아니다**
`rig_check`는 **저장해둔 화면을 재현하는지만** 본다. 대상이 화면 밖으로 나가는 나쁜 구도를
저장했으면 계속 OK를 띄우면서 같은 문제를 반복한다.
구도 자체는 **네 귀퉁이 테스트**로 확인할 것 — 대상물을 작업 영역 최좌/최우/최앞/최뒤에 놓고
4번 다 화면에 온전히 잡히는지.

## 같이 해두면 좋은 것

- 책상에 마스킹테이프로 **작업면·로봇 베이스·고정물** 위치 표시. 소프트웨어는 확인만 해주지 되돌려주지 않는다
- 에피소드 메타에 **`session_id`** 기록 → 나중에 시점이 틀어진 세션만 골라 뺄 수 있다

## 예: 실제 적용 사례

3색 분류 태스크(SO-101, 카메라 2대, 320x240)에 적용한 결과.
문제의 데이터셋은 ep59→ep60에서 카메라가 **59px(화면 높이의 25%)** 튀었는데 학습 실패 후에야 발견됐다.

설정: 씬캠 320x240, 비교 영역 `[0,0,320,94]`(벽 + 고정 용기 밴드, 팔·대상물 제외),
임계값 `--max-shift 2.2 --min-correlation 0.87`, 노출 3000 / WB 4600 수동 고정.

임계값 근거 — 같은 조건에서 두 번 독립 측정:

```
같은 시점 (로봇·대상물은 계속 움직임)   shift <= 0.6 px,  corr >= 0.929
카메라가 실제로 이동                     shift >= 52.5 px, corr <= 0.565
```

이 게이트를 넣고 150 에피소드를 재수집한 결과:

| | 이전 | 이후 |
|---|---|---|
| 시작 시 대상물 가시성 | 70~80% | **96%** |
| 화면 하단 잘림 | 6% | **0%** |
| 포화 픽셀 | 3.6% (자동 노출 시 16.1%) | **0.0%** |
| 최대 시점 이동 | **59px** | **4.1px** |

> ArUco 마커 방식(`rig_calib.py`, `make_markers.py`)도 들어 있지만 이 리그에선 쓰지 않는다.
> 마커를 작업면(옮겨지는 매트)에 붙이면 기준이 로봇 베이스가 아니라 매트가 되어,
> 정작 잡아야 할 매트-로봇 상대 변화를 가려버리기 때문이다.
> 작업면 자체가 매 세션 재배치되는 리그라면 그때는 마커 쪽이 맞다.
